# 领地石模组

领地石是独立的 common 模组，标识为 `scnet.territory`。需要服务器和客户端在各自的
profile 中安装同一模组；游戏不会自动启用它。

## 开发构建

模组通过 `SCNET.Survivalcraft` 和 `SCNET.ContentTool` NuGet 包构建。
在仓库根目录先按 [NuGet 包文档](../Doc/NuGet.md)生成当前 SDK 包，再执行：

```sh
dotnet build TerritoryStoneMod/TerritoryStoneMod.csproj
```

现有 ContentTool 构建目标生成
`TerritoryStoneMod/bin/Debug/net10.0/packages/scnet.territory.scpkg`。这是开发构建产物，
不会写入仓库的 `Publish/` 目录。通过游戏的模组管理安装该包，再选择包含它的 profile。

## 范围与权限

- 领地石所在格子始终为正方形范围的中心，`Size` 表示水平半径，不再按区块原点对齐。
  半径范围 4–32 格（9×9 至 65×65），默认 16 格（33×33）；保护贯穿世界高度，暂不支持高度分区。
- 每个主体最多一个领地，任意高度的领地都不能在 XZ 平面重叠。扩大范围时由服务端检查，
  无效尺寸或冲突会整体拒绝，原设置保持不变。
- 默认进入、离开、挖掘、放置分别配置。默认禁止进入、允许离开、禁止挖掘和放置。
  拥有者和管理员绕过这些限制；队伍关系不影响领地权限。主体授权是默认规则之外的允许项，
  不会禁止默认已经允许的操作，也不能授予拆除领地石的权利。
- 领地石自身仅允许拥有者或持有 `scnet.territory:admin` 的主体挖掘；设置仍只允许拥有者修改。
  该权限使用标准授权策略，GUI 房主、首个连接者和角色拥有者均不会自动获得领地管理权。
- 只有玩家及载有玩家的坐骑受通行限制，普通动物不受影响。
  边界只阻挡受限方向的移动；允许的离开、沿边行走或单纯上下移动不会触发进入拒绝提示。`tp` 等特权传送绕过行走边界。
- 领地只限制玩家通行及挖掘放置；不限制普通交互、骑乘、PvP、投射物、点火、火灾、爆炸
  或机械搬运，不提供全面防破坏保障。领地石自身保持不可被活塞移动，以保持范围中心稳定。

## 申请与授权

越权时只显示原因、领主及申请方式，不展开完整命令或完整地址，也不自动弹窗。申请由玩家主动发起：

```text
territory request <领主主体地址>
```

申请只指定领主，不填写权限，具体权限由领主审批时选择。命令补全会列出在线领主的完整主体地址，并显示可选昵称及地址缩写。
名称和角色 ID 不作为账户管理目标；没有角色的在线主体也能申请和审批。
审批和修改授权均通过 UI 勾选进入、离开、挖掘和放置权限。

已有授权记录的主体不能再次申请；越权时提示领主未允许该操作，并引导联系领主。
领主拒绝申请时明确通知申请人，并提示可以联系领主；拒绝不生成授权记录，
申请人仍可在限频间隔后重新申请。

双方必须在线。同一申请人只能有一个待处理申请，申请间隔至少 30 秒；申请两分钟后、
任意一方离线或领地删除时失效。每个领主最多 8 条待处理申请，整个世界最多 128 条。
领主收到逐条审批对话框，可自行选择四项权限或拒绝。已有窗口打开时等待其关闭；
关闭或返回审批对话框视为拒绝。通过后追加选定权限，申请人收到通知并重新进行操作，
不会自动重放原先被阻止的操作。

对准自己的领地石按 `G`，通过“主体授权”页签查看现有授权，支持离线主体。
选中列表中的主体后，使用底部“编辑权限”或“撤销授权”；撤销前需要确认。
“设置”页签保留范围、默认权限和边界显示，底部“应用”提交设置。切换页签不会提交或丢弃未应用的设置。
每个领地最多保存 128 个主体的授权。审批及授权管理也使用注册的 World 命令并在服务端
验证调用者身份；本地操作员身份不能替代领主主体身份。

内部审批和授权修改命令保留身份验证、远程传输能力，只供 UI 调用，不提供文本入口或参数补全。
文本入口只保留 `territory request` 及在线领主补全。
授权随存档保存并同步给客户端；未安装相同模组的客户端不支持此流程。

## 设置与边界显示

对准领地石按 `G` 或编辑按钮打开面板。修改半径和选项后点击“应用”；客户端等待服务端回执，
失败会恢复权威设置并提示原因。关闭面板不提交尚未应用的更改。

“显示领地边界”只控制外观。模组内嵌专用着色器，在全高度的四侧边界上绘制稀疏半透明网格，
视点附近显现，最远 24 格渐隐；自己领地为青色，其他领地为琥珀色。保留场景深度测试，
不写入深度，在天空和透明地形之后绘制，保留前景墙体与水面的正常遮挡；
不渲染实体墙，也不依赖游戏资源目录或额外图像库。Headless 不创建渲染资源。

## 数据与加载

- 方块资源 ID 为 `scnet.territory:territory_stone`；运行索引由目录动态分配并随世界保存，
  预览与世界实例各自持有编号。
- 领地记录位于 `Project.xml` 的 `ExtensionData/scnet.territory/territories`，包含领地石坐标、
  `Size`、`AllowEntry`、`AllowExit`、`AllowDigging`、`AllowPlacing`、`ShowBoundary` 和 `Grants`。
  领地归属和授权以完整主体地址为键，记录显示名称快照和四项权限，不保存临时申请。
- 服务端维护权威数据；完整快照、更新和设置回执传递相同字段。此版本不保留旧领地字段或消息格式，
  测试建议使用新世界；客户端和服务端必须加载同一个精确模组包。
- 方块表、数据库补丁、四种语言和着色器嵌入模组程序集，不重复放入 `data/`、`assets/`。
- 卸载模组不等于自动清理存档中的模组方块或扩展数据。

版本由 `SharedProperties/Versions.props` 的 `TerritoryStoneVersion` 维护；构建从
`manifest.template.json` 生成清单。当前改动只升级模组，不更改游戏联机协议。
