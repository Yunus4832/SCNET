# 领地石模组

领地石是独立的 common 模组，标识为 `scnet.territory`。需要服务器和客户端在各自的
profile 中安装同一模组；游戏不会自动启用它。

## 开发构建

在仓库根目录执行：

```sh
dotnet build TerritoryStoneMod/TerritoryStoneMod.csproj
```

现有 ContentTool 构建目标生成
`TerritoryStoneMod/bin/Debug/net10.0/packages/scnet.territory.scpkg`。这是开发构建产物，
不会写入仓库的 `Publish/` 目录。通过游戏的模组管理安装该包，再选择包含它的 profile。

## 数据与行为

- 方块运行索引为 264；与其他模组的索引冲突由现有注册目录检查。
- 领地数据属于当前世界，保存于 `Project.xml` 的
  `ExtensionData/scnet.territory/territories`，不使用跨世界静态字典。
- 服务端维护权威状态，客户端使用模组消息接收完整快照与增删改。
- 设置面板等待服务端结果；被拒绝的修改会恢复服务端设置并提示玩家。
- 领地始终保护挖掘和放置权限；“禁止非成员进入”单独控制行走，关闭后可穿越，仍不能挖掘或放置。无权限玩家若已在领地内，仍可离开，避免被困在出生点或重生点。
- 边界阻挡、挖掘和放置被拒时会提示原因；出生点可以圈地，已在领地内的玩家能够离开。
- 对准已放置的领地石后使用通用编辑键 `G` 或编辑按钮打开设置面板；普通交互键不打开面板。
- 设置修改仅接受领地拥有者；保护操作允许拥有者和管理员，团队许可由领地设置控制。
- 保护范围按 XZ 判断，不限制高度。边界显示与限制进入是独立选项；显示框高度不代表
  保护范围的高度。
- 方块表、数据库补丁与语言资源嵌入程序集，在模组入口显式注册；不重复放入包的
  `data/` 或 `assets/` 自动贡献目录。

卸载模组不等于自动清理存档。原有内置领地数据不自动迁入本模组；旧存档的领地修复仍由
原有存档升级工具处理。不要只依赖缺失方块回退空气来判断数据已被清理。
