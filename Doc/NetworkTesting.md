# 网络稳定性与容量测试

仓库提供 `NetworkDamageTool`，用于在本机客户端和服务端之间转发 UDP 数据报并施加可重复的
延迟、抖动、丢包和带宽限制。它是集成测试工具；其内部损伤决策和转发能力由
`NetworkDamageTool.Test` 覆盖。

```text
GUI Client -> NetworkDamageTool -> Headless Server
```

基本用法：

```bash
dotnet run --project NetworkDamageTool -- run \
  --listen 127.0.0.1:28989 \
  --target 127.0.0.1:28987 \
  --seed 12345 \
  --up-latency-ms 120 --up-jitter-ms 50 --up-loss 0.05 \
  --down-latency-ms 120 --down-jitter-ms 50 --down-loss 0.05 \
  --down-bandwidth-kbps 1500 \
  --events artifacts/network-run/proxy-events.jsonl
```

客户端必须显式连接代理监听端口。一个代理实例只服务一个客户端；多客户端实验为每个客户端
分配独立代理端口。代理在首次收到数据报时绑定客户端 UDP 端点；客户端进程重启后应同时重启
对应代理。代理保持 UDP 数据报边界，不解析 SCNET 包协议。

每个方向支持以下选项：

- `--up/down-latency-ms`：固定单向延迟；
- `--up/down-jitter-ms`：均匀分布的正负抖动；
- `--up/down-loss`：0 到 1 的丢包概率；
- `--up/down-bandwidth-kbps`：串行化带宽，0 表示不限速。

`--seed` 使随机决策可重复，`--events` 每秒写入累计的双向数据报、字节、转发和丢弃计数。
当前版本使用整个进程生命周期内的固定损伤配置，不支持同一进程内的分阶段断流脚本。

地形同步将区块拆成独立的不可靠小数据报，避免某个区块的丢失分片阻塞其他区块。客户端对仍处于
`NotLoaded` 的区块保留请求状态；请求超过 5 秒未完成时，如果已有部分分片，就通过可靠控制消息
发送缺失位图，服务端只从编码缓存补发缺失分片；尚未收到任何分片时才重新请求完整区块。服务端
完整区块请求与缺片请求均按坐标去重，且固定近距离双份发送已经移除。因此弱网实验的恢复判据
不应只是“连接仍在”，而应验证停止移动后视野内缺块能够自行收敛，并比较补发字节数和完整区块
重试次数。

已加载区块的单元格变化使用可靠有序的版本化增量。每条增量声明基线版本和连续的结果版本；
客户端只在本地版本等于基线时应用。增量早于完整快照到达时会暂存，发现版本断层时则使副本失效
并重新请求完整快照。涉及方块修改的弱网实验应同时验证最终方块值和内容版本收敛，不能只验证
区块已经加载。

Agent 执行弱网恢复和服务端容量实验时，应使用仓库中的 `scnet-network-stability` skill。
容量测试不能用少量客户端线性外推；应保留一个真实 GUI canary 客户端，并使用遵循真实连接、
bootstrap 和包协议的轻量负载客户端逐步增加并发。当前仓库尚未实现该负载客户端，因此在完成
它和服务端 tick/网络指标之前，最大并发容量仍属于未知量。
