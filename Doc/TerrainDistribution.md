# 地形内容分发

SCNET 地形包含两类不同的数据：

- 权威内容：由持久化数据或世界生成产生的单元格值和柱数据；
- 派生数据：各世界独立计算的高度和光照，以及仅客户端持有的切片哈希、CPU 几何体和 GPU 缓冲区。

两者不能共享隐式生命周期。区块具有碰撞数据并不代表已经可以渲染；区块可以渲染，也不代表
更新的权威响应可以覆盖其当前分配。

## 运行时边界

权威运行时通过 `AuthoritativeChunkGenerationPipeline` 恢复或生成内容。
`TerrainChunkContentAuthority` 发布不可变快照。`ServerChunkDistributionScheduler` 负责请求去重、
优先级和完整快照发布，绑定所属 Authority Project。网络编码、缓存与缺片重传由该节点的连接适配层负责，
完成的编码任务仍须经过发送预算，不能直接发送；世界关闭后停止接收请求并释放待发送内容。
尚未生成的内容保留在请求队列中，直到就绪或离开客户端兴趣范围，不将正常生成等待作为失败返回。
Client 每轮地形更新重新按当前兴趣范围和距离选择最多 64 个请求，不等待半秒时间窗；
未获本轮名额的区块不进入重试等待，下轮仍可立即请求。请求提交成功后才记录重试时间，
已发请求保留五秒恢复窗口。每条整区块请求消息也最多含 64 个不同坐标，网络传输入口对较大列表分批，
逻辑消息与字节解码都校验数量、分配代数和内容版本。
编码准备和发送都按更新循环推进，不等待整秒发送窗口。

本地角色出现时先提交最多 64 格的准备需求，进入游玩前检查近处区域。
准备完成后由视图提交配置中的完整视距；准备阶段与绘制阶段的需求切换需分别观察。

Authority 与 Client 分别通过所属世界的阶段调度器推进工作，按实际执行耗时为首显、维护与必要前置条件
分配服务机会，不采用固定的生成步骤比例。Authority 计算自己的逻辑高度与光照，不生成客户端网格；
独立 Client 计算副本的显示光照并继续完成渲染派生。

权威世界调度器只负责兴趣范围、请求去重、分配身份和完整快照捕获，不区分进程内与网络连接，
不持有编码缓存或分片发送状态。每个客户端每轮最多发布四个完整快照；每个客户端最多暂存四个尚未交给连接的
完整快照，暂满时保留原请求。新的分配身份会取消旧身份的排队快照和发送进度，迟到的旧请求不能
替换当前分配。

网络连接通过 `NativeTerrainDelivery` 将完整快照转换为物理分片。同一权威节点共享一份编码器与
缓存，每个连接独立维护发送进度和预算；编码使用已经接收的固定快照版本，不追逐持续变化的地形。
区块释放后，尚在执行的旧编码结果不能写回缓存。

对于每个客户端，缓存快照的优先级综合考虑当前位置距离，以及根据近期移动计算出的未来 0.75 秒
中心位置预测。这样既能优先发送移动方向上的区块，也不会让玩家身后较近的区块长期饥饿。网络连接的发送量
同时受 `ServerChunkCountSendPer`（每秒启动的新传输）和 `ServerChunkBytesSendPerSecond`
（每秒编码内容字节，默认 128 KiB）限制。该字节预算用于网络编码后的分片载荷，不能以原始单元格数组大小直接推算区块发送时间；进程内完整快照不经过这条带宽限速路径。每个连接持续补充数量与字节额度，首次获得一个区块、
一个分片的启动额度；空闲最多累计一秒额度，字节容量至少能容纳一个分片。新传输、续传和缺片恢复
共用预算，每个连接每轮最多排队 64 个分片，不能因空闲或多次模拟更新形成无限突发。

大区块按分片消耗额度，预算不足时保留进度，下一轮继续，不允许超预算整块发送。
每连接最多保留 4 个活动传输、4 MiB 编码内容；更近的请求可抢占较远的保留项，离开兴趣范围、
分配身份变化或连接退出会释放对应进度。传输固定不可变快照版本，不因权威侧持续编辑而反复重启，
后续内容变化沿增量协调器衔接。

编码后的区块被拆分为 352 字节的应用层分片，连同包头和帧头适配安全 MTU 下的 419 字节可用预算（扣除 DTLS、封装与中继预留）。每个分片都能装入一个 `Unreliable`
`TerrainFragment` 数据报，因此 LiteNetLib 不需要为地形维护大型、不透明的可靠分片消息。
客户端根据分配身份和内容版本进行重组，接受乱序和重复分片，并在常规的五秒区块请求重试之间
保留已经收到的部分。

重试时，如果客户端已经拥有部分分片，就发送有界的缺片位图；服务端只从编码快照缓存中补发
位图指定的分片。缺片控制在网络连接层处理；无法从缓存恢复时转为普通完整区块请求，
经相同的权威兴趣范围和分配身份校验。每个区块使用一条控制消息发送位图，元素数量不能超过协议规定的最大分片数，重复索引不能绕过该上限。
系统不使用固定的近距离重复发送，因此恢复流量只用于仍然缺失的分片。坐标被重新分配时，旧
`AllocationGeneration` 的部分传输会被丢弃。只有完整解码的快照才能进入客户端安装队列。
已完成的传输身份会保存在有界集合中，防止迟到的重复分片重新创建组装任务。
重组器最多保留 64 个未完成传输，并预留最多 16 MiB 的分片与完成副本内存；达到限额时不创建新任务，
后续请求仍可重试。同一分配的旧内容版本和冲突形状不能重置较新的组装进度，每个分片长度必须与索引一致。

客户端只接受自己已经请求、仍然存活的分配身份；释放或替换分配会取消其重组和待安装快照，
迟到分片不能重新创建已取消的任务。完整解码但尚未安装的快照按分配合并，共用 16 MiB 容量；
背压拒绝和解码失败不会把该传输永久标记为完成。运行时关闭立即清空这些接收状态，资源释放时解除订阅。
网络解码前预留完整快照容量；已经解码但仍在消息收件箱中的快照也计入上限。进程内连接使用同一
预留机制，暂满时保留发送消息并重试。投递成功时容量转入内容队列，取消、丢弃或处理失败时释放；
被丢弃的网络完成结果仍可按同版本重试。

远程副本使用具有容量上限的分配滞回策略：区块在 `ContentDistance` 内分配并请求，但已经分配
的区块只有离开 `ContentDistance + 32` 格后才满足空间淘汰条件。活动内容范围之外最多保留
256 个区块，超过容量时优先淘汰最久未进入活动范围的区块。这样既能让已加载内容和几何体在
短距离高速往返时继续复用，也不会让缓冲区随可视距离无限增长。

保留环中尚未完成的区块继续保存其部分分片，但在重新进入活动内容范围之前不会继续发起网络
请求，因此历史缓存不会与当前可游玩区域争夺带宽。

所有 Client 通过 `ClientChunkContentTransport` 接收内容消息，包括单机和 GUI 开服的进程内 Client。
`NativeTerrainReceiver` 在网络连接边界完成重组、解码和缺片请求转换；世界处理器不接收分片。
完成的快照与进程内完整快照进入同一 `TerrainSnapshotMessage` 处理器。
包处理器只将完整快照和版本化单元格增量加入队列，不直接修改地形数组或地形状态。地形更新循环持有访问门时
排空传输队列，并通过 `ClientChunkContentCoordinator` 安装快照。
`ClientTerrainDeltaCoordinator` 根据已安装的快照版本对暂存的单元格增量排序，然后再应用。

远程客户端在本地完成挖掘或放置时，通过 `ClientTerrainPrediction` 为目标添加临时网格覆盖。
光照派生、网格生成及邻面判断读取 `GetCellValueForGeometry`，预测变化和撤销均重新计算光照。
派生阶段只写光照位与高度缓存，不把预测方块内容写入真实单元格；碰撞、存档、掉落和方块行为
不受内容覆盖影响，放置物品的扣除也只由服务端处理。服务端处理挖掘结束或放置事件后返回
请求标识与最终区块内容版本，客户端等待相应权威
数据后结束覆盖；目标单元格变化、快照安装、区块释放或三秒超时也会结束覆盖。
拒绝操作时展示当前权威状态，不把操作前的值写回地形。此流程需要客户端与服务端使用同版协议。

本地玩家的挖掘射线会命中预测放置的方块，命中尚未确认的操作目标时不发送挖掘请求。
预测移除也不会让挖掘射线穿透真实方块。确认、拒绝或超时结束预测后，正常输入可继续操作；
物理碰撞和其他地形射线仍只读取真实内容。

单机与 GUI 开服通过 `InProcessMessageConnection` 接通独立 Authority 和 Client，使用相同的
准入、请求处理器、权威调度器及内容版本规则，不直接读取权威快照数组。进程内连接不监听端口，
传递拥有独立单元格与轴数据的完整快照，省去编码、分片、重组和网络带宽限速；每次调度最多提交四个完整快照。
客户端不创建磁盘地形序列化器或临时伪存档，已安装内容只保存在自己的 Terrain 中；磁盘序列化器与保存队列只属于权威世界。
两种连接传递相同的方块内容与气候数据，由客户端重新派生光照和高度；
共用分配身份、内容版本校验、接收队列上限和安装流程。

`TerrainCellAuthority` 是权威单元格读写的唯一目标。保存操作遍历同一份权威地形；持久化背压
拒绝接收快照时，权威区块不能被释放。同步写入失败会向保存调用者传播，区块保持脏标记，修复存储后重试成功才清除；正常关闭世界必须完成保存后再释放运行时。各 Project 明确拥有 `Authority` 或 `Replica` 内容角色，
单机和 GUI 开服也有独立的两份存储及地形工作线程。主线程提交消息、安装完成的快照并为 Client
更新 GPU 资源，Authority 不持有地形渲染器。

进程内投递按区块坐标合并。释放权威区块分配时，也会取消尚未安装到副本的快照。
`AllocationGeneration` 仍然是最终的陈旧响应保护，但普通的本地移动不能仅仅因为玩家快速跨越
分配边界就不断积累过期快照副本。

植物、常春藤生长与落叶季节变化的延迟改块由 `SubsystemCellChangeQueue` 在权威更新线程处理。
20 个游戏秒的周期或容量阈值只启动批次，之后每帧最多检查 32 项、使用约 2ms 的软预算续作；
单个改块及其业务回调不可抢占。批次通过持久请求非阻塞取得前台执行机会，暂停地形工作线程，
但不持有访问门执行业务回调。按坐标合并最多保留 10000 项，新意图满时返回拒绝，调用者保持
自然状态等待后续轮询，关联的作物/土壤或季节/落叶意图一并接受或拒绝。应用时校验原内容
（忽略光照位）及区块分配代次；已卸载或换代的意图不应用。未应用自然意图与原有机制一样不作为
持久事务保存，关闭后由正常扫描恢复；已经应用的地形修改照常保存。立即执行的初始化变化保留
同步语义，不再用同步全量排空应对队列压力。常春藤仍每 60 个游戏秒提交生长意图，再由共享自然改块队列排空，可能等待下一次 20 秒批次；目标已被占用时丢弃，队列拒绝时保留到后续周期重试。

## 身份与版本不变量

每个已分配坐标都有单调递增的 `AllocationGeneration`。请求和响应都携带
`(coords, allocationGeneration)`；属于旧分配的响应会被忽略。

每个权威快照都有 `ContentVersion`。客户端只会为当前分配安装更新的版本。安装内容时必须持有
地形访问门；内容到达使本块的高度与光照修订失效，并使已安装邻块的光照修订失效，邻块高度不随之重置。

同一 `Terrain` 生命周期内，同坐标的内容版本在区块释放后仍保留，新分配从更高版本开始，
加载存档继续推进该序列。不能按新 `TerrainChunk` 对象重新从零计数，否则仍持有旧副本的客户端
会误丢后续增量，并把较低版本的操作确认当成已完成。版本无需跨世界或进程持久化：新连接
会重新安装完整基线。版本记录与分配代次共用坐标表，普通单元格写入不增加额外查询。

已完成初始化的权威区块发生单元格修改时，发布可靠有序的 `TerrainCellDelta`，其中携带
`BaseContentVersion` 和 `ResultContentVersion`，结果必须恰好是下一个版本。只有客户端当前
安装版本与基线版本一致时，增量才会被应用。

增量早于对应快照到达时会被暂存，并在快照安装后回放；快照版本已经达到或超过增量结果版本时，
该增量视为陈旧数据。版本断层会标记需要完整快照，并复用常规快照请求及重试路径恢复。已有内容
继续提供碰撞和画面，不退回未加载状态；缺失的增量补齐后也可直接结束恢复。完整快照与
增量修改因此共享同一条内容版本序列，不再作为相互独立的同步路径。

接收暂存与版本协调各自最多保留 8192 条增量，每区块最多 256 条；相同版本的重复消息不重复占用额度。
接收暂存每轮最多取出 1024 条，在区块间轮转，未处理部分留在队列中。未请求或已经释放的分配不接收增量。
超过上限时清理该区块的待处理链，合并记录必须恢复到的最高内容版本，经普通快照请求重新同步；
比该版本更旧的快照不能结束恢复。释放分配或世界关闭会清理相应缓冲和恢复要求。恢复要求在安装
同轮快照之前处理，避免丢弃一份本来足够新的快照。

有界暂存溢出会记录警告并请求完整快照。HTTP 区块诊断中的 `NeedsContentSnapshot` 应在安装达到恢复要求的内容版本后归为 `false`，可结合队列清空验证恢复收敛。

客户端主线程在取得地形工作线程的互斥令牌后，通过 `ClientChunkContentApplication` 应用内容。
每轮最多处理 256 个操作，默认时间预算为 4 ms；恢复版本要求先于快照，快照与普通增量交替取出。
未取出的内容继续留在原有受限传输队列中，不转移到另一份无界主线程缓冲。
预算在操作之间检查；单次快照安装及其每区块最多 256 条增量回放不可抢占，可能越过本轮时间预算。
因此这是一轮工作的调度上限，不是每帧耗时的硬保证。

本地和远程 Client 遵循相同的版本规则。权威单元格写入通过内容增量消息投递给观察者，
由各 Client 的增量协调器推进已安装版本，不直接修改同进程副本数组。

客户端 CPU 几何体携带 `ClientGeometryContentVersion`，用于判断派生结果是否对应当前
`NetworkContentVersion`。绘制门禁则单独记录当前分配是否已有 GPU 几何体上传完成：初次加载必须等待几何体上传；
同一分配中的连续增量或完整快照更新，可以继续绘制上一版已上传几何体，直到替代几何体完成。
新快照安装会使 CPU 派生修订失效，防止旧后台任务冒充新内容的重建结果。
GUI 托管服务器显示自己的独立 Client 副本，使用与远程 Client 相同的 GPU 几何可见性规则，
不根据 Authority 的模拟光照派生状态控制客户端几何体。

## 派生数据可见性

权威内容通过连续单元格增量发生变化时，旧几何体不再是当前版本，但在新内容完成光照、顶点生成和
GPU 上传之前仍可作为视觉占位；同一分配的版本断层恢复和完整快照刷新也遵守此规则。
真正释放后重新分配的区块不继承旧内容或 GPU 几何体，必须等待初次安装和重建；保留缓存的租约续建遵守下文保留环的确认规则。

光照或相邻区块到达也可能使派生数据失效，但这种情况并未改变权威内容。此时已经上传的当前几何体
可以继续绘制，直到替代的光照和几何体构建完成。上传替代几何体时只释放旧 GPU 缓冲区，不能清除
对应的实际上传输入标记；设备重置使绘制门禁失效并重新准备上传，同一分配的快照刷新不能冒充新内容已完成 GPU 上传。

这种区分可以同时避免以下两种错误：

- 区块重新分配后显示属于旧分配的几何体；
- 仅仅因为连续内容增量或光照正在重新计算就制造可见空洞。

GPU 上传在每个客户端世界中共享每帧 4ms 的软预算，多个摄像机不会分别重置预算。首显与维护轮流获得上传机会，类内优先近处视点，并定期服务最老候选。候选年龄按整帧视点并集维护；未进入本地当前视点、最近视点或已应用可视需求范围的派生结果暂不上传。预算控制下一整块上传的开始，单次驱动调用仍可能超时，不能把它理解为整帧耗时上限。工作线程正在占用几何数据时，本次上传尝试跳过该项，避免渲染线程等待该锁。

## 线程所有权

每个世界拥有独立的 `TerrainAccessGate` 和 `TerrainWorkExecutor`。所属世界的更新线程在短访问事务内安装内容或改块，地形工作线程使用同一访问门读取和写入可变数组。业务生命周期回调在世界更新线程执行，不能依靠数组修订号代替互斥访问。

权威区块的初始业务规范化使用一个持久前台批次暂停后台计算，并交回该批次的访问租约；回调中的单次改块仍通过短访问事务完成。初始化入口要求调用者先释放访问门。前提在交接期间改变时延后初始化；未捕获的业务初始化异常会关闭当前世界并上报异常，避免保留无法完成初始化的活动区块或重放已执行的副作用。

卸载先预留保存容量，再交回访问租约执行业务回调；重新取得访问权后校验分配身份，捕获回调产生的最终脏数据，然后释放区块。重入驻留请求由所有者延期，不能消费外层尚未完成的前台请求。未捕获的卸载回调错误，或回调破坏当前卸载租约、分配身份时，关闭当前世界，避免重复已经执行的通知副作用。世界完成清理后只向宿主发出一次停止通知，异常关闭不会重新保存半完成状态。

自动保存与明确保存由逻辑线程捕获已修改驻留区块的独立数组及项目数据，压缩和区域文件写入由同一地形写入队列处理，不在项目数据捕获阶段同步写盘。整世界保存使用专用的单个批次槽，普通卸载仍有独立的有界名额；同一世界不能积压多份完整保存输入。新输入内存与本次脏驻留区块数成比例，每块约 258KiB，不能将其当作固定小缓冲。

写入按队列顺序执行：更早的卸载、完整保存、之后的新卸载不会倒序覆盖。捕获后只清除已转交快照对应的脏标记，后续修改继续标脏；失败快照保留，可用于重载及后续保存重试，不能提前归还池化缓冲。`Project.xml` 在该保存批次及更早地形写入成功后才提交，地形失败或项目数据捕获失败均通过保存结果报告，关闭与等待保存会排空相关工作。

`HasContents` 表示内容已经发布、可用于碰撞和逻辑计算；权威快照描述、完整基线及实时增量还要求 `IsContentInitialized`。生成完成钩子先在世界更新线程执行。生成结果通过线程安全可用性信号和持久前台请求交接；普通更新不等待访问门，获取票据或提交暂时受阻时下帧续作，已经执行的钩子不会重放。每次取票也限制陈旧候选的清理数量，避免过期队列一次性阻塞更新。内容发布后继续推进逻辑派生与初始业务规范化；规范化产生的改块并入第一份基线，不提前发送实时增量。`AreBehaviorsNotified` 只是通知前置防重入标记，不能当作初始化完成。正常初始化完成后重新计算光照不会重复业务初始化。

高度、日照与传播分别维护请求及完成修订。逻辑读取使用明确的能力，例如 `HasCurrentHeightData` 和 `HasCurrentLight`，不依赖一条混合生成、光照与渲染的综合状态链。权威世界和客户端副本分别计算自己的派生结果，客户端预测不能影响权威规则光照。

`TerrainComputationScheduler` 按阶段维护就绪任务和反向依赖等待关系。内容、高度、日照、可续作传播和网格交接由每世界的串行工作线程协调；客户端网格在所属地形协调线程生成。等待依赖或异步结果的任务显式挂起，不反复出队扫描。Core 通过不依赖渲染类型的 `ITerrainDerivedWork` 接收客户端任务，服务端不注册网格任务。已驻留邻区即使在活动范围之外，也可以作为必要前置条件推进；依赖请求完成或取消后解除等待关系，不互相等待邻区的最终综合就绪状态。

调度区分近处必要内容、首显、维护和后台工作，按协调线程实际执行耗时分配服务机会。23/24 生成器沿用独立树木基础数据的并行预热；评估总计算工作量时须同时统计这些 worker，不能只比较协调线程计时。一个阶段完成后重新判断下一阶段的类别，仍有实际等待者的前置工作保留必要的优先级提升。同一类别内优先距离较近的任务；老化任务插队后，后续距离优先任务须累计获得该次插队耗时三倍的执行时间，才能再次插队。没有插队需求时仍按距离正常执行，不积攒插队额度；单个阶段不可抢占，因此该比例是后续补偿规则，而非瞬时耗时上限。这样避免昂贵的旧内容任务持续挤占新产生的高度与光照阶段。依赖区块的当前计算阶段同时继承所有活动等待者中的最近距离，并沿多层依赖传递，只覆盖被等待的阶段及其前置阶段，不提升无关后续工作；原始视距距离单独保留，等待解除、取消或位置变化后重新计算，避免遗留距离提升。服务类别间仍按耗时分享机会，因此不承诺严格的同心圆完成顺序。客户端关闭表现资源前同步解绑任务。

客户端的 `ClientTerrainContentPump` 独立负责收包应用、请求排序和重试，服务端不装配该服务。它通过持久前台请求完成访问交接，其他前台操作或网格唤醒不能消费尚未完成的交接请求。优先中心来自已应用的地形需求，排队中但尚未应用的位置不能提前改变请求或安装顺序。

已有上传几何的维护重建会合并短时间内反复变化的输入：等待约 50ms 的稳定窗口，连续变化时最多延后 200ms；首次显示、已开始且输入仍有效的第二遍构建以及交互同步补算不等待。延期任务显式挂起，由客户端更新循环按当前分配身份恢复，不在后台忙轮询。

客户端网格使用所属世界的几何生成上下文和切片缓存，沿用串行阶段交接与旧 GPU 几何保留规则。

客户端的 `TerrainChunkPresentation` 独立维护网格两阶段构建与上传状态。CPU 就绪后可以单独发布，不等待网格；权威世界不拥有区块表现存储。网格结果带有分配代次、内容版本和本地重建批次，提交及上传前均校验，过期结果不能覆盖当前数据。旧的已上传几何可保留至替换完成。

区块视觉资源由每个客户端世界的 `TerrainChunkPresentationStore` 持有。卸载时先释放表现资源，再释放 Core 区块；关闭世界时先在访问门下解绑表现任务，再释放渲染器及表现存储；Core 随后停止地形工作线程。设备重置也须取得地形访问门。

光照依赖由调度器登记和唤醒；每次执行一个任务阶段或一段可续作传播，不使用递归相邻区块推进。

## 验证关注点

修改地形生命周期时，验证分配代次与内容版本的陈旧响应门禁、快照/增量顺序、释放与重载，
以及工作线程和主线程的所有权。修改派生数据或绘制门禁时，还应观察真实 GUI 的初次加载、
连续修改、移动往返及重新同步，不能仅凭内容加载成功判断无缺块。

涉及网络请求、重试或收敛的变更需使用受控损伤场景，比较同构建的无损基线与恢复结果。
测试规模按实际变更选择，不将任意地形改动都扩展为完整多人测试矩阵。
可重复实验方法见 [网络测试](NetworkTesting.md)，Agent 执行与证据管理由
`scnet-change-validation`、`scnet-debugging` 和 `scnet-network-stability` 技能负责。

### 地形增量的有界合批

连续发布、同一接收运行时和相同受众的单元格增量在逻辑发送队列中合批，每条消息最多64个增量。顺序和值、基线版本和结果版本逐项保留；不会跨过其他控制消息合并，也不会合并已经进入投递或重试的消息。批次仍计入原有字节上限和消息上限，正常区块更新突发不再逐格占用一个收件人名额。

完整区块内容在逻辑路由上归属 Bulk，内容暂存已满时只背压该通道，不阻挡同一连接的 Control 消息。进程内连接同样遵守这一区分，不模拟网络刷新周期。

流体表面标记与光照一样由邻居内容派生，不推进权威内容版本；实际液位、方块内容等逻辑数据修改仍推进版本并发布增量，避免为没有对应增量的派生修改制造版本断层。

保留环中的区块重新进入活动范围时会续建客户端内容租约，拒绝旧租约的迟到交付并重新确认基线。确认期间保留旧碰撞和已上传画面；新租约基线到达前只缓存增量，不在旧基线上应用。内容版本未变化时允许当前新租约的同版本基线完成确认，但不接受更旧内容。真正的增量版本断层仍请求完整快照，同一次恢复等待期间不逐条重复警告。

### 视距边界与远景雾

地形驻留、分发与派生任务使用区块矩形覆盖判断，并在需求中心周围保留 8 格准备余量，
使相机在两次需求更新之间移动时，视距边缘仍有可用内容。实际绘制仅包含矩形与配置视距相交的区块，
不再按区块中心整块裁剪。首次淡入从相机到区块矩形的最近距离开始，保证首帧被雾遮住。
雾量在片元阶段限制到最终范围，避免跨边界三角形因顶点过早截断而在远端仍留有可见部分。

客户端每个视图先将天空、日月、光晕与云绘制到可复用的背景纹理，地形远景雾采样同一屏幕方向的背景，
随后以深度测试合成天空。天空只绘制一次，不进行 CPU 像素读回；代价是一张与当前渲染视口同尺寸的
RGBA 背景纹理、一次背景合成以及地形片元的额外采样。水下、岩浆和关闭天空的场景继续使用相应固定雾色。

### 出生准备与加载等待

首次出生选点等待区域内容可用，沿用现有准备范围与进度判定。已有角色的服务端就绪检查、
客户端首屏等待及实体同步流程采用原有实现。

加载界面分别等待初始世界快照与本地角色到达，使用各自的提示和计时。角色等待上限覆盖
服务端两个各 15 秒的出生准备阶段及连接等待余量，避免将角色尚未出生误报为快照超时。

首次进入世界时，角色等待和首屏视野准备统一由 `GameLoadingScreen` 展示。手动提交角色创建后
返回加载页，保留正在处理的创建请求；角色实体和既有首屏就绪条件满足后才切换游戏画面。
首次进入期间角色视图隐藏准备对话框，游戏内复活继续使用角色视图的原有展示流程。
