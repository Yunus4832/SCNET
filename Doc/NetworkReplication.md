# 网络复制与兴趣路由

本文描述当前代码中的网络边界，不是全部玩法或服务器容量的验收报告。
可重复的网络实验方法见[网络测试说明](NetworkTesting.md)。

## 游戏网络代码组织

`Game.Network` 根名称空间保留节点、连接、运行角色和 P2P 房间生命周期。其余代码按职责划分：

| 名称空间 | 职责 |
|---|---|
| `Game.Network.Handling` | 消息注册、解析入口、分发与业务处理器 |
| `Game.Network.Transport` | 受众、收发上下文、发送策略、投递统计关联与快照合并 |
| `Game.Network.Chunks` | 游戏区块编解码、分片生成、缓存、编码队列与传输限制 |
| `Game.Network.Replication` | 空间兴趣、实体与区块兴趣跟踪、电路变化跟踪 |
| `Game.Network.Snapshots` | 从游戏对象采集协议快照及恢复游戏数据 |
| `Game.Network.Diagnostics` | 网络路由、发送、编码与兴趣统计 |
| `Game.Network.Interpolation` | 远端位置、旋转和速度的插值 |

协议契约与线格式仍由 `Game.Protocol` 提供。玩家离线请求由 `SubsystemCharacters` 收集，在玩家遍历结束后统一处理。

## 包、受众与接收上下文

`Game.Protocol` 定义 `IProtocolMessage`、消息记录、兼容整数、通道编号和显式二进制编解码。
`IProtocolMessage` 只包含消息类型编号；最低客户端状态由游戏的 `ProtocolReceivePolicy.MinimumState` 决定，
载荷由协议编解码器处理。协议记录不携带发送连接、收件人、组件或世界对象。
游戏在允许读取世界的线程采集稳定快照，处理器依据上下文验证并执行业务。

节点通过显式 `PackageHandlerCatalog` 装配处理器。准备阶段目录只接受握手与启动消息，
世界资源目录就绪后、Project 构造前，由应用安装该世界的完整目录。处理器实例由
`WorldNetworkBinding` 按世界缓存，关闭时清理；模组路由由实际世界目录捕获。
本地进程内客户端与远程客户端分别装配客户端目录，权威目录由宿主提供。
`ProtocolPacketCodec` 原子校验整个批次的格式，`WorldNetworkBinding.Dispatch` 再判断处理器与执行侧。

游戏模式、季节、玩家外观类别和库存拖拽方式的枚举由游戏持有，协议仅传 `byte`；
游戏通过 `ProtocolEnum` 集中转换和校验，在应用前拒绝未知取值。通信流程与载荷标签枚举仍由协议持有。
`Engine.Network` 不引用游戏协议；游戏和薄客户端组合协议与传输。
HTTP、文本和 UI 入口都在客户端适配为命令对象，再共用二进制编码发送命令标识、参数字节和关联编号。服务端解码后按实际连接玩家鉴权执行，不解析 HTTP 请求或待执行的原始文本。命令目录查询同样使用普通命令，仅返回授权后的命令标识；HTTP 参数说明由本地适配器补充。
游戏根据完整的 `CommandResult` 决定发布范围后转换为 `CommandResponse`；服务端发布策略不上网，
所有命令请求统一返回关联结果；协议不记录请求入口身份，也不区分 HTTP 与界面的响应模式。客户端依据关联编号匹配本地调用上下文，决定返回给等待中的调用者或展示结果。

应用数据报使用小端 `int32` 长度前缀、压缩应用帧及 MessagePack 消息数组批次；每条消息使用显式数字 Union 标签和数字 Key 字段。
`ProtocolPacketCodec`、`ProtocolFrameCodec` 和 `ProtocolMessageCodec` 分别处理这些边界。
格式错误会拒绝整个批次，不执行已解码的有效前缀。
纯区块分片重组和缺片位图算法由协议库共用；世界兴趣、缓存、生成/解码、背压与应用仍归游戏。

- 出站使用 `OutboundPackage(Package, Audience)`，由 `PackageAudience` 表达全局、单个连接、连接集合或排除连接。
- `NetworkSender` 提供按区块、位置及实体观察者选择受众的入口。
- 客户端上行请求可使用 `NetworkSender.SendToServer`，只绑定所属运行时的服务端连接；权威运行时或缺少服务端连接时拒绝调用，不回退为广播。
- 入站解码生成 `ReceivedPackage(Package, Context)`。`PackageReceiveContext` 保存节点、服务端角色及发送连接，延迟处理和嵌套包继续保留同一上下文。
- 处理器必须检查包方向、发送者权限和操作对象；AOI不是权限检查的替代品。

`RuntimeMessageInbox` 对本地与网络消息统一限制为最多 1024 条、128 MiB 载荷计费。
计费代码从协议契约生成，不通过序列化计算长度，也不代表托管堆的精确占用。
每轮接收默认最多计费 2 MiB、耗时 4 ms，并遵守调用方的消息条数限制；
为保证大消息最终能够处理，每轮允许首条消息超过本轮字节预算，处理器执行期间不会被抢占。
同一发送者保持 FIFO，不同发送者轮转；处理期间新加入的消息留到下一轮。
连接取消后的消息不会交给处理器，出队、清空或容量不足时清理取消项都会释放其所有权和计费。

逻辑发布队列最多保留 8192 条、64 MiB 载荷计费；明确单一收件人的消息另受每连接 2048 条、16 MiB 限制。
借出进行分发的消息继续占用额度，尚未处理的消息按原发布顺序回队，不会被新发布抢占重试容量。
已分发消息的回压续项保留原顺序；关闭世界会取消相应租约并归还额度，不投递到后续世界。
单个收件人过载时清理其定向积压并安排断开；聚合发布端过载时安排停止该端点。处理这些生命周期动作
留在更新线程，发布方不阻塞等待客户端。区块快照的预留不足只返回背压，调度器继续等待。
`PendingLogicalPackageBytes` 包含尚在分发的借出消息，与底层网络待发送计费分别报告。

连接发送接口只在返回 Accepted 时接管一个投递续项；回压、关闭或抛出异常时，续项仍由调用方持有。
逻辑分发把连接的 I/O 或释放异常按关闭处理，继续其他收件人；适配器程序异常在清理未转交续项后
仍向上抛出。已接受的投递不重复取消，尚未处理的借出尾项按原顺序返回队列。

逻辑路由每轮最多展开 1024 条消息，默认载荷计费预算为 4 MiB、时间预算为 4 ms。
未展开的消息保持原顺序留到后续更新；首条消息允许超过字节预算以保证进度。
预算在消息之间检查，一条消息展开为多个收件人的过程不可抢占；该预算不包含后续网络编码和发送批次。

底层网络调度另有每轮最多 1024 条检查、4 MiB 载荷计费及 4 ms 的预算，每个连接每轮最多取出 64 条消息。
连接按轮次轮换；消息放不进本轮剩余字节预算且所属连接尚未发送时，该连接保留下轮优先机会。
未发送内容仍保留在原队列中。
刷新间隔按连接和通道分别记录，一个连接的刷新不会推迟另一个连接的首次发送。
预算在批次之间及取消息时检查，单个批次的编码和发送不可抢占，可能越过时间预算。

传输层可靠发送额度耗尽时，保留尚未发送的消息并在后续轮次重试，同通道内按原顺序恢复。
重试放在后来发布的消息之前，已成功进入传输层的批次不会重发。若已有更晚的同键快照排队，
旧快照的重试直接退役，不覆盖新状态。编码后的批次超过连接单次发送上限时按顺序拆小；
单条消息仍超过上限时安排断开该连接，不把无法发送的消息无限重试。

底层待发送队列每连接最多保留 2048 条消息、16 MiB 载荷计费，所有连接合计最多 128 MiB。
快照合并按替换后的计费检查容量；替换无法容纳时，旧消息及其投递统计仍保持完整。
达到上限时拒绝当前消息、清理该连接的积压并安排断开，其他连接已接受的消息继续保留。
连接释放及世界关闭会归还对应计费；网络诊断中的 `PendingNetworkPackageBytes` 显示此项总量。
这些额度统计底层网络待发送内容，不包含逻辑路由和传输层自身的可靠发送队列。

逻辑发送遇到背压时，同一连接、同一通道的后续消息一起等待，避免小消息越过尚未投递的消息；
其他连接和通道仍可继续投递。重试消息排在本轮发送期间新发布的消息之前。

客户端命令结果、补全和权限快照，以及队伍提示与快照，只接受所属端点的规范 Server 连接。
本地玩家身份从该端点的 Self 获取，不使用同进程另一世界的全局会话。

受众中的连接按对象身份匹配，而不是按可复用的客户端编号匹配。集合受众在构造时
复制成员；调用方随后清空或复用工作集合不会改变已入队包的收件人。
快照合并显式比较类型、实体ID和受众成员，新旧连接即使编号相同也不能混合快照。

客户端的 `Server` 与 Peer 标签使用同一规范物理连接对象；`NetNode.Clients` 只记录实际物理连接。
其他玩家的逻辑名单由所属世界的 `WorldConnections.Members` 保存，人数由 `PlayerCount` 计算，
不为远程玩家创建没有传输的 `Client`。实体快照通过 `CharacterControllerSnapshot` 携带角色、
玩家主体地址及连接生命周期元数据，不携带宿主认证 Token。

权威世界在发布连接元数据之前分配递增的 `ConnectionGeneration` 和随机 `ConnectionEpoch`；
同一连接的 Bootstrap 重试保持这组身份。客户端按路由槽位保留代际与已移除记录，拒绝旧代快照，
同代元数据必须匹配 epoch、玩家主体与已绑定角色。新代连接使用新逻辑记录，旧受众不会指向它。
状态更新与移除消息必须匹配当前连接的完整生命周期，旧连接的移除消息不能删除新连接。
未知生命周期的移除不会提前推进槽位代际；名单加入与移除共用可靠有序 Control 通道。

实体快照和初始名单可能从 Bulk 通道晚于 Control 状态更新到达；同代快照仅补充元数据，
不覆盖已有记录的连接状态。持续状态变化由匹配生命周期的 Control 消息应用。
真实本地 Self 的初始身份只能通过经过验证的名单绑定，实体快照不能替代该步骤。

DTLS 持钥验证后，连接先作为临时传输存在。`ServerAdmissionController` 下发当前连接挑战，
分别验证开放模式确认、服务器密码或外部认证方签名批准。临时连接只能发送准入凭证，不能分发游戏业务包，
不进入公开客户端名单，也不触发角色恢复或 Bootstrap。通过策略后再次检查模组、重复在线、封禁和人数，
才建立正式会话并进入原有世界加载阶段。准入等待独立于名单投递确认，不占用其他玩家的加入确认窗口。

游戏加载页在准入期间使用挑战期限，成功后重新计算普通 Bootstrap 等待期限；取消、超时和断线清理临时连接。
服务端私有策略读取 `ExtensionData/game/admission`，其密码校验值不进入公开描述或世界初始化快照。
远程加载页已接入密码输入和外部认证的首次信任、浏览器及轮询。GUI 主机使用相同策略完成可信进程内准入，
先加载世界并开放监听，本机玩家通过准入后才恢复角色；等待本机准入不阻止服务器运行，普通单机不请求外部认证。配置和目录安装已接入，重启后重新执行准入，协议和边界见 [认证协议](Protocol/AuthenticationProtocol.md)；完整多端运行验收仍需按实际环境执行。准入通过消息仅在策略与业务检查均通过且轮到该连接进入名单同步时发送，
排队期间继续使用挑战期限，不提前消耗普通 Bootstrap 等待时间。

角色创建请求只传名称、皮肤及角色类型，不传完整角色存档。服务端使用安全连接已验证的主体地址
建立归属，拒绝空身份、重复创建及无效外观资料；等级、出生状态和权限来自服务端默认值。
世界存档加载和实体进入基线仍使用服务端保存的完整角色数据，不属于客户端创建请求。

`PackageTransportPolicy` 只决定通道、可靠性、压缩和刷新策略，不能决定空间受众。
投递声明使用 `Engine.Network.DeliveryMode`，`PackageTransport.Delivery` 保存投递方式；通道编号由协议共用；投递方式、刷新和合并策略仍由游戏定义。
包解码入口接收字节载荷和显式接收上下文；网络层负责关联 Client，解码器不查找传输连接或通过端点推断身份。
接收上下文绑定 `WorldRuntimeContext`，明确接收侧是 `Authority` 还是 `Client`，并提供该侧绑定的世界。
处理器通过 `context.Project` 访问接收世界，不根据全局当前世界选择目标；发现阶段的上下文没有世界绑定。
游戏项目在构造回调中、子系统加载前绑定运行时；子系统通过 `WorldRuntimeContext.For(Project)`
取得所属端的角色，一个项目不能同时属于两侧。持久化电路、库存同步等世界业务根据
`IsAuthority` 判断权威侧，不能根据应用的全局模式判断；需要连接信息时使用 `WorldNetworkBinding.For(Project).RequireNode()`，Core 世界上下文不持有节点。
表现资源使用所属运行时的 `HasPresentation` 判断：只有 GUI 进程中的 Client 具备表现能力，
GUI 进程中的 Authority 也不创建环境音、天气声音或地形渲染器。权威地形完成模拟光照后停止派生，
不以客户端网格就绪状态冒充权威内容就绪；区块几何和绘制缓存按需创建。
`GameRuntime` 分别持有 Authority 和 Client 的运行时与 Project，禁止两侧共用消息节点。
会话统一处理各节点消息，并按权威端、客户端顺序推进世界；节点不自行订阅窗口帧。
客户端世界可以独立释放或重建，完整退出则尝试清理两侧世界和端点，即使一侧清理失败也继续另一侧。
单机不使用独立的世界运行角色，端点始终是 Authority 的 `Server` 和 Client 的 `RemoteClient`；
是否允许本地菜单暂停由会话策略决定。离线 GUI 会话打开本地游戏菜单时暂停两侧模拟，
消息泵和界面继续运行；GUI 开服或远程会话不暂停权威世界。关闭本地客户端会解除暂停，
保留的 Authority 可以继续运行。世界时钟不查询其他角色的 GUI，睡眠加速只由 Authority 的完整玩家集决定。
传输提前关闭会使活动接收上下文失效，但所有权层仍保留待保存、释放的 Project，直至资源清理完成。
磁盘权威世界由宿主层 `AuthorityWorldProjectFactory.Create` 构造，客户端 Bootstrap 由应用侧 `WorldProjectFactory.CreateClient` 构造，
后者只清理自己接收运行时中的失败资源。Bootstrap 和初始快照确认携带显式接收运行时，
加载界面只确认对应运行时；世界保存始终选择权威 Project。
一个上下文不能重新绑定其他世界。世界释放或节点角色切换后，旧上下文关闭，排队中的旧消息不再分发到后续世界。
处理器按工厂注册，由各运行时分别创建并保存实例；同一消息族在一个运行时内共用处理器，
不同运行时不共用命令限频等可变处理状态。取消注册后旧实例不再参与分发，世界关闭时释放其引用。
网络解码后的消息进入所属运行时的有界 `RuntimeMessageInbox`，由节点更新阶段按消息预算交付，
不在网络回调中直接重入游戏处理器。处理过程中重新排队的消息留到后续处理阶段，
连接取消或世界关闭会阻止陈旧消息交付。进程内连接使用同一收件箱和协议值校验，
只传递独立捕获、已转移所有权的逻辑负载，不经过字节编码和分片。
每个 `OutboundPackage` 显式绑定来源 `WorldRuntimeContext`，逻辑队列、原生延后队列及连接发送都校验
该来源仍是节点的当前运行时。运行时关闭或替换会清理其待发项并结算已有 fanout，原生批次在编码后、
实际发送前再次校验；不同来源的快照不能合并，旧发送项不能因节点复用而转向新世界。
世界业务通过 `NetworkSender.Send(project, package, audience)` 或相应的空间投递方法发送，
世界关闭后不再向节点的后续运行时排队。聊天、组队提示和资料更新也按命令上下文或角色所属世界选择节点；
`GameMessageService.Publish` 使用所属运行时，权威端选择受众，客户端只向该运行时的服务端提交。
该发布入口在世界关闭后拒绝投递和写入历史。库存待同步队列由各世界的 `SubsystemInventories` 持有，
节点更新只刷新自己绑定世界的队列。
`NetNode.QueuePackage` 用于节点自身的投递入口，必须显式传入受众，不提供单参数默认广播重载。

服务器发现通过 `Engine.Network.NetworkHost` 收发：`SendDatagram` 必须提供目标地址，空地址抛出异常；LAN 发现由 `BroadcastDatagram` 单独发送，不以空地址暗示广播。游戏节点和发现探测各自持有宿主，游戏包解析和刷新策略留在游戏层。
客户端请求使用 `SendToServer` 并显式提供所属 `WorldRuntimeContext`；世界内广播和空间投递
从所属 Project 取得节点，会话定向回复使用该会话的拥有节点，不默认访问全局网络节点。
连接阶段确认也定向绑定服务端连接。
显式Global仍须按业务语义审查，不能仅因调用已编译就判定空间路由正确。
本地玩家通过独立客户端运行时和 `InProcessMessageConnection` 接入权威世界，不把玩家直接激活到权威 Project。
已准入但等待名单确认的状态持有 `Client` 会话记录；原生和进程内连接共用 Bootstrap 入口。
既有进程内客户端的名单通知按 FIFO 投递，原生连接仍等待可靠投递确认后开始新客户端的 Bootstrap。
会话的连接状态由 `IMessageConnection` 决定，不以是否有 Socket Peer 判断。逻辑发送先进行共同受众
选择；网络适配器按接收者排队并保留通道刷新、合并与分包策略，进程内适配器直接排队到对端
收件箱，不等待网络刷新周期。运行时生命周期取消会使已排在另一侧的旧连接消息失效。

雷击通知保留全局天空闪光语义；雷声由客户端按水平距离判断（近雷40格、远雷200格）。
客户端通知仅重放表现，不重新执行雷击生物统计或权威伤害/爆炸逻辑。

## 统一兴趣状态

`SpatialInterestIndex` 用64格二维网格维护兴趣覆盖及连接中心候选，点、区块和事件半径
查询对候选做精确圆形距离判断；半径查询按空桶面积与已占用桶数量选择邻桶或现有位置记录，
避免在稀疏场景遍历大量空桶或重复查询批准位置。连接按引用身份索引，
批准相机位置后立即更新；统一兴趣轮次补齐位置并清理断线。初始快照对其单一接收者直接
核对批准范围，不依赖第一次分桶轮次已执行。索引不保存独立的客户端权限或模拟状态。

`SubsystemNetworkInterest` 查询客户端批准的地形分发位置，必要时使用玩家位置。
区块相关性统一由 `NetworkTerrainPolicy.IsChunkRelevant` 判断批准范围圆与区块矩形是否相交；
共享兴趣查询、初始区块实体快照、地形请求、队列清理和分片重传使用相同边界。
地形分发在发送前重新清理已离开批准范围的请求，不采用区块中心加固定余量的另一套授权。
地形分片独立发送，速率由区块调度器的发送数量和字节预算限制；不查询没有发送方的
旧地形可靠队列。地形恢复通过应用层缺片请求完成，不依赖可靠整区块通道。
`EntityInterestTracker` 分开保存生物、拾取物、投射物、移动方块、方块实体和库存兴趣组，
避免不同类型的相同数值ID相互干扰。状态按连接对象隔离，断线清理不会延续到新连接。
断线连接的实体兴趣清理由统一兴趣子系统每轮执行，各复制子系统不再重复维护连接清理。

实体进入需发送完整状态；离开和真实销毁是不同事件。常规状态快照缺少某个ID
不代表该对象已删除。局部状态不能依赖全局Bootstrap全集代替进入基线。

骑乘事件发送前为每个既有观察者补齐尚未观察的骑乘依赖组成员；创建基线与骑乘事件
共用有序 Bulk 通道，避免新坐骑尚未创建时事件被忽略。已有实体不重复创建。
身体碰撞只依赖内容就绪，不等待光照、网格或 GPU 上传。普通水平移动按身体占地范围检查前方区块，
在进入未知内容前仅截断对应轴的位移和速度，仍可后退或沿已知边界侧移；内容到达后自动放行。
碰撞脱离也不能把身体推到未知区块中，未完成内容阶段的已分配区块不作为物理方块读取。
初次出生、传送等使身体中心尚在未知内容中的情况仍等待内容就绪，避免在空白数据上模拟下落。
骑乘者及坐骑所处地形未达到身体可模拟状态时，身体移动暂停，距离脱离计时也暂停并清零；
恢复地形后继续原距离/时间判据。死亡导致的下马不依赖这一地形前提。
自动下马由权威运行时维护；客户端只为本地角色提交下马请求，不控制非玩家骑乘者。

跌落和火焰伤害沿用运动控制侧的报告方式：客户端为本地角色及其坐骑报告，
权威端不再为这些远程控制对象重复计算同一次环境伤害；没有玩家控制的生物由权威端直接处理。
实际扣血、恢复生命及伤害钩子只在权威运行时执行，客户端接收权威结果。
生命同步和伤害结果携带权威死亡时间，客户端应用结果不会再次运行死亡统计或掉落规则。
受击、失血、击杀及死亡记录通过统计快照单独同步给角色所有者，重复快照替换这些权威字段，保留客户端维护的移动等统计。
生存统计使用独立字段投影；网络应用部分统计时保留未包含的战斗记录与移动计数。
生存状态和结果只接受权威到客户端方向。客户端不能提交耐力数值或选择疾病结果；耐力预测接收权威快照校正。
权威根据速度及位置变化计算活动消耗，现有位置/速度上报仍是后续移动反作弊需要校验的边界。
睡眠请求只表达入睡意图；唤醒请求携带睡眠起始时间，权威核对所属角色、当前睡眠轮次、手动唤醒策略和最短持续时间。恶心/呕吐状态携带效果序号和剩余时长，重复或迟到的旧效果不重启粒子与延时消息。
耐久消息区分普通变化、攻击和最终销毁；它与实体基线、删除共用有序 Bulk 通道。
客户端在销毁通知中播放碎片与声音，并等待实体删除；兴趣离场和迟到基线不重放销毁效果。
燃烧状态允许零剩余时长表示权威灭火，客户端不根据自己的水体碰撞提前改变燃烧状态。

这些规则根据所属运行时与角色控制关系决定，不依赖单机或开服模式。

睡眠导致的世界时间加速只由权威运行时根据完整玩家集合决定。客户端的实体集合
受 AOI 裁剪，不能据此判断所有玩家是否睡眠；客户端保持正常步进并接受服务端世界时间。

玩家运动使用10Hz完整状态快照，而非只发送变化字段：每次包含当前位置、旋转、速度、
视角及适用的骑乘/梯子/潜行状态。静止状态也能在一次丢包后的后续快照中恢复，
不依赖下一次移动触发补发。待发同玩家、同受众快照直接替换为最新状态，不合并旧字段；
快照的骑乘标志必须与接收端当前父身体关系一致；事件和运动跨通道到达时不把坐骑坐标
回落为玩家坐标，也不把上马前的玩家坐标套给坐骑，等待后续匹配的完整快照恢复。
未设置的梯子等可选状态不会被旧快照重新带回。相比增量包，静止时载荷增加，
但服务端仍只向兴趣观察者发送，不为此恢复全局广播。

生物身体使用完整状态快照，经 `StateStream` 发送，客户端按实体比较 `StateTick`。
同一自包含快照携带独立 Pose 的攻击/进食状态和阶段，客户端只推进表现，不生成权威攻击命中。
按连接载荷上限再次拆包时，所有分片必须保留原轮次；序号丢失会使接收端将新位置当旧状态拒绝。
拆包按实际编码后的载荷大小计算，不能仅凭生物数量假定适合直连或中继路径。

拾取物恢复创建基线会纠正已有对象的位置、数量、值、速度和粘附状态，不重放拾取声。
拾取物批量创建只来自当前连接的兴趣进入集合；定向恢复请求也重新校验位置相关性，
不存在读取整个世界拾取物集合的独立全集同步协议分支。
拾取物位置按最多24项的小包发送到StateStream，兄弟小包不由Sequenced互相淘汰；
客户端只平滑跟随权威位置，不重复执行碰撞、脱离方块和拾取飞行模拟，避免旧地形与快照互相拉扯。
接收端按对象比较StateTick，忽略重复或旧轮次，创建/恢复基线同时建立该对象的轮次下限。
在线玩家概要覆盖所有已生成的在线玩家，不受实体AOI限制，供玩家列表计算远处玩家距离和方向。
概要仍为完整列表原子替换，使用可分片的可靠有序Bulk传输，待发列表合并为最新值；
它不是实体移动快照，丢包时可能等待重传，不能拆成会互相覆盖的独立玩家列表。
移动方块创建基线只恢复对象，不播放活塞声；实际伸缩通过独立的 `PistonSound` 瞬时效果投递。
基线及磁盘保存保留运动原始起点和当前速度，重入不把当前位置重新当作平滑加速起点。
实体着火基线直接恢复剩余燃烧时长，不经过权威点火入口；客户端加载不会因权限隔离丢失状态，服务端加载也不重复发送点火事件。
音效等一次性表现使用 Effect 通道，创建、删除与停止仍走可靠生命周期通道。
投射物音效范围根据未缩放的听觉阈值计算，不读取服务端本地音量偏好；接收端继续负责衰减和静音。

方块实体（箱子、熔炉等）按区块观察者建立独立进入/离场生命周期，不再全局广播创建或删除。
初始快照按其坐标过滤；进入基线先于库存增量使用同一有序 Bulk 通道发送。
熔炉进度及停止燃烧的最终状态也使用该通道，避免状态先于实体基线到达而被忽略。
完整熔炉基线包含剩余燃烧时间、热量和熔炼进度；实体离场后重入不依赖下一次增量才能恢复进度。
容器打开响应也使用 Bulk；通过空间授权但尚未观察该方块实体时，先补发完整实体基线，
再返回库存 ID 打开响应，避免跨通道抢先到达导致点击无响应。
箱子、工作台、发射器和熔炉的方块移除回调统一交给方块实体子系统处理销毁：只有权威世界掉落库存并删除实体。客户端地形增量可以先移除方块外观，但容器实体与库存仍由实体复制的删除消息释放，不再次执行掉落。
非空间、非身体实体仍按其全局业务语义复制。

物品栏的移动、交换与加工由 `InventoryOperations` 在 Authority 执行，网络处理器先检查槽位和玩家访问权。
控件只进行可行性检查并发送请求，不提前扣除副本物品或执行加工；本地和远程都由权威同步更新槽位。
快速移动按单一目标槽的剩余容量提交实际数量，避免客户端按整组数量重复请求。

可编辑方块的界面提交必须传入所属 Project，通过 Client 请求进入 Authority 的校验与修改流程。
休眠、自伤、弩上弦、物品抛出和发射器配置也使用所属 Client 的请求路径，单机与 GUI 开服不再从
控件直接执行服务端操作。界面的临时显示数据不等于已经提交的权威结果。
告示牌编辑器保存时只发送请求，不提前改副本文字；权威端对打开与保存统一检查冒险模式只读、空间访问资格和目标方块类型，接受后同步内容。

家具界面的创建、改名、移动、删除和导入都通过所属 Client 世界提交请求；单机、GUI 开服和远程客户端
使用同一处理流程。Authority 分配或修改家具数据后再同步到 Client，界面不直接调用 Authority 处理器或
在副本中分配设计。`FurniturePackageHandler.Submit` 必须显式传入界面所属的 Project。

家具设计是世界级 ID 引用，不随观察者离开区块而删除。设计回收同时考虑地形、
现存物品与离线玩家序列化库存；玩家恢复期间，在库存实体实际加入世界前仍保留离线引用。
在线库存实体已存在后忽略同一玩家的旧离线快照，避免旧库存永久阻止未使用设计回收。

库存的状态观察与操作权限分开：方块容器只向已建立方块实体基线的观察者复制，身体库存按实体观察者及本人连接复制。
玩家库存操作只允许所属连接；方块容器请求使用统一兴趣中心检查空间访问资格。
这里的空间访问资格是兴趣距离，并非玩家到容器的近距离交互限制；不能据此宣称已防止远距离操作。
统一兴趣子系统保留原始相机请求，并周期按最新权威玩家位置重新审批，更新地形生成与分发中心。
位置状态和视野请求跨通道到达时，首次裁剪的中心不会永久滞留；断线同时清除请求意图。
观察到状态并不等于获得修改权限。领地设置请求另外核对实际发送会话的主体地址与领地主体身份，
领地模组的设置与消息契约由模组自身维护，详见
[领地石说明](../Mods/TerritoryStone/README.md)，不属于内置游戏复制协议。

区块附属状态离场时发送 `ChunkStateResetPackage` 清理客户端缓存；
进入时也先发送清理包，随后发送该区块的告示牌、
可编辑方块和火焰基线。清除与基线使用有序Bulk通道；世界级物品定义和家具设计ID
不属于区块清除范围。

## 发送诊断

电路同步保留20Hz权威时间步，使用连接级完整基线、变化电压及移除坐标。
可见电压仍由统一区块观察者筛选；没有变化时仅发送时间步和空集合。
客户端先重建权威缓存，为待应用时间步创建独立完整状态，再按原电路步推进纠正。
在对应时间步恢复已存在的持久状态元件，并将输出变化的邻居安排到下一步；
随机发生器、锁存器和计数器在客户端使用权威持久值，不独立推进随机或锁存状态。
离场移除和重新进入的值变化由同一连接缓存比较产生，重连建立新基线。
该线格式没有旧协议兼容分支。跨区块电路在加载就绪后完成无损及弱网断网返回的收敛验证，
这不代表冷加载瞬时完成，也不代表所有电路逻辑已经穷举测试。

启用HTTP命令服务并鉴权后，可使用 `game:diagnostics/network/get`：

```json
{"identity":"game:diagnostics/network/get","arguments":{}}
```

返回累计统计及瞬时队列状态：

- `Interest`：当前世界服务端周期性兴趣协调更新的次数、累计/最大耗时及当前线程分配字节。包含该更新中同步调用的区块进入回调和包构造；不包含其他子系统独立调用空间索引的成本、异步工作、后续编码/发送。没有世界时为null；客户端未执行协调更新，计数为0。耗时是墙钟时间，不是进程CPU；分配不是存活堆大小。随世界子系统创建重新计数。
- `Channels`：每通道发送批次数 `Batches` 和编码后字节数 `EncodedBytes`。
- `Packages`：每包类型、通道的实际收件人投递次数 `Deliveries` 和未压缩载荷字节数 `PayloadBytes`。
- `Fanout`：每包类型、通道已完成逻辑消息的数量、不同收件人投递数及平均/最大扇出。消息在出队后建立身份，合并前被替换的快照不单独计数；零收件人消息参与平均值分母。拆片与延期副本共享身份，同一连接只计一次，不同连接即使数值ID相同也分别计数。延期被替换或停止时取消仍保留此前已发送的收件人；尚未完成的消息暂不进入累计值。连接上的直接发送计为单收件人，未连接UDP和发现广播不计入。这里的投递指交给传输库，不代表客户端已确认接收。
- `Routing`：逐连接逐通道筛选的候选检查数、选中包数、累计和最大单轮毫秒数；包括通道与受众资格筛选，不包括兴趣集合构建、序列化、压缩或发送。
- `Encoding`：此NetNode的成功批次编码尝试数、包数、原始和编码字节，及写包序列化/帧编码累计毫秒数。包含尺寸探测、拆包和重试造成的重复编码，不表示实际投递量；帧编码包括压缩策略选择与封装，不是纯压缩耗时。独立宿主上的服务器发现广播不属于 NetNode 实例，未计入；地形预压缩缓存构建也不在此计时范围。
- `PendingPackages`：采样时尚未出队的逻辑包数量，包括拥塞延后重试，不等于传输层数据报数。
- `ReliableQueues`：采样时各连接尚未收到传输确认的可靠载荷字节数（`PendingBytes`），由 Engine 统计；这是瞬时值，需要定期采样才能发现峰值或持续积压。

同一个包发给多个客户端会分别计数。载荷字节与压缩后的批次字节不可直接相加，
也不能把批次数当成包数。统计不包含UDP/IP或传输库开销及重传，因此不是网卡流量。
比较带宽应取同一受控场景和时间窗口的前后差值，并记录玩家数量、位置、视距和事件。
空世界累计值或单包合成测量不能证明整服收益。

Engine 传输宿主为中继信封统一预留 46 字节，因此初始安全 MTU 的应用载荷预算为 419 字节（同时扣除 DTLS 与封装开销）。区块分片固定使用 352 字节载荷，连同元数据和帧头适配该预算；直连也使用这项保守预算，避免连接路径影响区块重组格式。


逻辑连接目标由 Engine 定义：`AddressNetworkTarget` 保存 DNS 名称或 IP 和端口；
`InvitationCodeNetworkTarget` 保存控制地址、六位码和中继策略；`InvitationSessionNetworkTarget`
保存控制地址、不透明会话 ID 和策略。`NetworkHost.PrepareConnectionAsync` 使用调用方提供的 HTTP 客户端，
自动读取信标 UDP 配置并准备同 socket 路径；邀请准备结果保留会话目标，不携带可序列化的票据或参与凭据。
邀请控制通道仅允许 HTTPS，loopback 实验可使用 HTTP。此 API 不负责游戏模组准备或 session 持久化。
信令 HTTP 失败统一返回 `RendezvousException`，保留操作路径、`Kind` 分类、服务端错误码及 HTTP 状态。
`NetworkHost.Resources` 提供连接、待握手、信令请求、候选、注册、邀请、中继准备、路径及通知的近似实时计数，
供实验检查资源收敛；不是跨线程原子快照。宿主停止后这些计数归零，完成所有等待中的传输操作。
游戏加入界面按分类显示本地化提示，诊断日志保留错误码；调用方主动取消保留 `OperationCanceledException`，
不转换为网络故障。联机码或会话不存在、会话满员、容量限制、授权失败及中继不可用可以分别处理。


P2P 房间是监听宿主上的可选注册，世界配置默认关闭且地址为空。实例安装服务的选择复制地址和名称，不保存安装记录引用。
普通监听和世界加载就绪后，通过 Server 域命令注册；本地控制者、获权玩家和 System 共用处理器。
`P2PRoomStatus` 提供 Disabled、Registering、Active、RetryWaiting、Stopping 状态、期望启用值、有效码及最后错误。
失败按 4、8、16、30 秒退避重新注册，恢复时获取新房间；注册失败不影响普通直连或 LAN。
运行时停止取消注册、续期、协商及重试，收集迟到结果并注销，保留监听和既有玩家路径。
同配置开启幂等；停止清理中拒绝重新开启；旧任务不改变后续生命周期。运行时配置不自动保存。
独立服务器注册成功输出六位码；只读网络诊断的 `P2P` 返回完整状态快照。
HTTP 客户端和取消源保持有效直到注册结果被收集、房间注销结束；不在帧循环等待未完成任务。
Engine 按 SessionId 清理自身端点注册、候选及未连接中继准备；已连接中继按连接生命周期保留。
`InvitationRelayPolicy` 仍是加入方的中继偏好，不是房间启停状态；公网信令使用 HTTPS。
本地控制及 GUI 玩家 HTTP 入口见 [命令权限模型](CommandPermissions.md)，用户命令见 [独立服务器](Server.md)。


GUI 推荐从信令服务器分类的房间列表连接；“联机码”保留为次要操作。联机页固定提供连接、添加、收藏、刷新、联机码和删除：局域网与外部源禁用添加、删除，信令分类另禁用收藏；选中和加载状态继续约束操作。切换分类不重建操作列表。信令服务在内容页面安装和管理。
设置的“诊断与兼容”页面通过点击轮换选择实例级的中继策略，作为房间列表的加入策略和联机码对话框的初始值，联机码操作可单独覆盖本次策略，默认允许；它与世界房主开服配置分别管理，不预设公共信标地址。“恢复兼容设置”同时将中继策略恢复为允许。
房主在游戏菜单的更多操作中查看邀请状态，状态持续刷新，显示该次注册对应的信标地址并允许复制有效码。
联机客户端在游戏菜单的统计信息中查看连接方式：直连、P2P 直连或中继；单机和房主不显示这条客户端信息。
邀请不加入本地收藏或最近服务器标签，正式连接仍验证游戏协议、模组和玩家身份。
连接关闭时显示本地化原因与“确定”按钮，返回服务器列表；邀请用户可再次输入联机码，重新获取路径和服务器信息。
Android 后台可能受到系统网络限制，不保证后台保活或无缝恢复。传输连接关闭后，游戏停止向该连接发送数据，
并在前台处理断线事件，不能继续使用旧连接或因发送到已关闭连接而崩溃。
连接预检与服务器模组核对共用可取消等待对话框；取消按钮或 Esc 会中止请求及下载，
释放尚未转交的连接准备资源后回到列表，不再进入世界或确认重启。


游戏 `ServerConnectionPreparation` 在模组准备等待期间每 20 秒续约路径；消费或关闭时先停止维护。
续约失败不会把旧预检结果当作仍有可用路径，转交前会报告错误。正式连接之后，准备注册被释放，
连接的交通保活和中继数据生命周期由 transport 独立维护。准备对象的并发关闭共享完成状态，
等待同一次资源释放，不会提前报告关闭完成。
取消未消费的中继准备、连接断开或关闭 Host 时，通过当前路由密钥认证的 `relay-close` 控制报文通知中继；
重复通知不会影响其他路由。中继结束转发并释放 socket，端口池清理后可重新分配该端口和新的路由密钥。
通知丢失时保留一分钟空闲回收作为边界。关闭邀请不撤销已建立中继路由，其存活由认证流量维护。
新的中继端点若仍被活跃连接、连接申请或握手占用，房主不确认该分配，每秒重试等待释放，
不更换已有路径或使整个邀请失效。中继准备探测预算为十二秒，仍受整体十五秒准备期限约束。
连接记录各自路由 ID，迟到的断开事件只能释放其原路由，不能按复用端口删除新路由。

信令服务 HTTP 按来源 IP 限流，`Rendezvous:HttpRequestsPerMinute` 默认 600；部署时按同时准备的
参与者数量配置该预算，同一 NAT 下的玩家共享来源 IP。房间目录与邀请控制请求分别计数，浏览不会耗尽续期额度。它与 UDP 注册限流和中继端口池容量分别管理。

### 信令房间目录与加入

联机页面的信令服务器分类从当前实例已安装且启用的服务读取公开房间。第二个筛选按钮先提供“全部”，汇总所有启用服务的房间，再列出各个服务供单独筛选；房间行标明来源。个别服务访问失败不丢弃其他服务的结果。目录浏览只发送HTTP读取，不创建参与者或申请中继；点击房间后使用其联机码及当前服务地址进入已有连接准备流程。手工联机码为独立的底层入口：直接填写信令URL、六位码及本次中继策略，不要求预先安装服务，不更改全局策略或安装列表；提交后使用相同准备路径。房间不收藏、不写最近记录或本地服务器目录。中继策略是加入方的实例偏好，独立于世界P2P设置；列表展示的可用方式不保证实际穿透成功。

连接发送结果区分接受、暂时背压和关闭。暂时背压时保留具有原运行时与收件人身份的消息，下一轮
继续交接，不作为断线处理；关闭或替换运行时时清理这些消息。完整地形快照交给网络适配器后，
其发送统计寿命覆盖后续物理分片，取消和完成均只释放各自持有的份额。

同一传输会话在准入和连接名册更新时保留连接对象，只更新身份及角色元数据。名册中的其他玩家
不是与当前客户端直连的传输端点。连接关闭会取消其尚未投递的消息；完整快照的容量预留随投递、
取消或丢弃释放，不随名册更新重置接收进度。

权威世界通过统一准备入口创建，不因是否监听网络而创建“服务器自身玩家”。`Clients` 名册只保存
实际玩家，玩家 ID 从 1 分配；0 仅表示客户端所连接的权威传输端点，不出现在玩家名册中。客户端
从当前消息的传输来源绑定服务器连接，重复名册保留现有玩家会话对象，不依赖一条虚拟服务器记录。
世界内的本地交互查询使用该世界的 `WorldRuntimeContext.LocalCharacter`；应用 UI 通过
`GameManager.LocalCharacter` 选择当前客户端会话。网络诊断按命令上下文的世界节点收集数据，并
标明运行时 ID 与角色，避免将客户端地形状态与权威发送计数混在一起。

通用消息在发布进入节点队列时捕获契约负载，发送方在发布后修改原数组、列表、字典或 JSON 不会
改变已排队内容。进程内连接另为接收方分离可变负载，接收方处理也不能修改同一次发布保留的网络
发送内容。不可变标量与值对象可以共享；完整地形快照使用已有的显式数组捕获及容量预留路径。
重试和适配器分片传递已经拥有的数据，不重复从发送方的业务对象取值。

### 方块燃烧的模拟与表现

燃料计时、随机扩散、烧毁及熔岩对邻近方块的改变只在权威世界执行。客户端维护复制的着火位置用于环境火声，不推进燃料计时或自行修改地形。烧毁碎屑通过 `BlockBurnEffectPackage` 发给附近客户端，使用 Effect 通道；事件区分碎屑、烧毁与流体接触嘶声，客户端按距离和每帧预算播放；流体接触只播放音效，不生成碎屑。水与熔岩的扩散、邻居更新队列和反应由权威世界推进，客户端只派生水面显示标志并计算本地环境音；两种方向的水熔岩接触共用表现事件。进程内连接与网络连接使用相同消息及处理器，权威世界不构造粒子或访问纹理。

### 生物与投射物表现状态

变形只由 Authority 决定。`CreatureShapeshiftStatePackage` 携带转换开始时间，Client 重放淡出、声音与粒子；转换状态也写入实体基线，供重新进入兴趣范围或恢复世界时使用。鲸鱼呼吸由 Authority 的独立计时控制，`CreatureWhalePlumePackage` 发布喷气开始和停止，Client 的鱼类模型只更新喷气表现，不运行呼吸 AI。这两类状态与实体基线共用 Bulk 可靠有序通道，避免状态先于实体创建到达。

投射物创建基线可携带烟迹大小、结束时间和颜色。Authority 不构造烟迹粒子，Client 按剩余时长创建，过期烟迹不重放。呕吐的模拟持续时间不依赖粒子是否注册或播放完成；燃烧的接触检测由 Authority 推进，火焰粒子与环境声只由 Client 创建。

进程内连接断开与网络连接断开都会结束客户端运行时，并保留踢出等断开原因；停止本机客户端不会同时关闭继续运行的 Authority。分片修复元数据在协议层验证，归一化和收件箱入队异常在网络接收入口隔离，不能中断服务端世界更新。

角色创建界面始终在客户端世界提交创建请求，包括单机和GUI本机加入；是否提供网络监听不影响该流程。权威世界只处理请求和角色存档，不参与创建界面的自动导航。
