# 网络复制与兴趣路由

本文描述当前代码中的网络边界，不是全部玩法或服务器容量的验收报告。
可重复的网络实验方法见[网络测试说明](NetworkTesting.md)。

## 包、受众与接收上下文

`IPackage` 只包含类型ID、最低客户端状态及载荷读写，不携带发送者或收件人。

- 出站使用 `OutboundPackage(Package, Audience)`，由 `PackageAudience` 表达全局、单个连接、连接集合或排除连接。
- `NetworkSender` 提供按区块、位置及实体观察者选择受众的入口。
- 客户端上行请求可使用 `NetworkSender.SendToServer`，只绑定当前服务端连接；单机、服务端或缺少服务端连接时拒绝调用，不回退为广播。
- 入站解码生成 `ReceivedPackage(Package, Context)`。`PackageReceiveContext` 保存节点、服务端角色及发送连接，延迟处理和嵌套包继续保留同一上下文。
- 处理器必须检查包方向、发送者权限和操作对象；AOI不是权限检查的替代品。

受众中的连接按对象身份匹配，而不是按可复用的客户端编号匹配。集合受众在构造时
复制成员；调用方随后清空或复用工作集合不会改变已入队包的收件人。
快照合并显式比较类型、实体ID和受众成员，新旧连接即使编号相同也不能混合快照。

客户端的 `Server`、`Clients[0]` 与 Peer 标签使用同一规范连接对象。
重复名单元数据在 GUID、Peer 不变时更新该对象，而不是替换对象使已入队确认包失去收件人。

玩家创建请求只传名称、皮肤及角色类型，不传完整玩家存档。服务端使用发送连接的GUID
建立身份，拒绝空身份、重复创建及无效外观资料；等级、出生状态和权限来自服务端默认值。
世界存档加载和实体进入基线仍使用服务端保存的完整玩家数据，不属于客户端创建请求。

`PackageTransportPolicy` 只决定通道、可靠性、压缩和刷新策略，不能决定空间受众。
投递声明使用 `Engine.Network.DeliveryMode`，`PackageTransport.Delivery` 保存投递方式；通道与包刷新策略仍由游戏定义。
包解码入口接收字节载荷和显式发送者上下文；网络层负责关联 Client，解码器不查找传输连接或通过端点推断身份。
`NetNode.QueuePackage` 必须显式传入受众，不提供单参数默认广播重载。

服务器发现通过 `Engine.Network.NetworkHost` 收发：`SendDatagram` 必须提供目标地址，空地址抛出异常；LAN 发现由 `BroadcastDatagram` 单独发送，不以空地址暗示广播。游戏节点和发现探测各自持有宿主，游戏包解析和刷新策略留在游戏层。
客户端请求使用 `SendToServer`；连接阶段确认也定向绑定服务端连接。
显式Global仍须按业务语义审查，不能仅因调用已编译就判定空间路由正确。

雷击通知保留全局天空闪光语义；雷声由客户端按水平距离判断（近雷40格、远雷200格）。
客户端通知仅重放表现，不重新执行雷击生物统计或权威伤害/爆炸逻辑。

## 统一兴趣状态

`SpatialInterestIndex` 用64格二维网格维护兴趣覆盖及连接中心候选，点、区块和事件半径
查询对候选做精确圆形距离判断；半径查询按空桶面积与已占用桶数量选择邻桶或现有位置记录，
避免在稀疏场景遍历大量空桶或重复查询批准位置。连接按引用身份索引，
批准相机位置后立即更新；统一兴趣轮次补齐位置并清理断线。初始快照对其单一接收者直接
核对批准范围，不依赖第一次分桶轮次已执行。索引不保存独立的客户端权限或模拟状态。

`SubsystemNetworkInterest` 查询客户端批准的地形分发位置，必要时使用玩家位置。
区块相关性统一由 `NetworkTerrainPolicy.IsChunkRelevant` 判断批准范围圆与区块矩形是否相交；
共享兴趣查询、初始区块实体快照、地形请求、队列清理和分片重传使用相同边界。
地形分发在发送前重新清理已离开批准范围的请求，不采用区块中心加固定余量的另一套授权。
地形分片独立发送，速率由区块调度器的发送数量和字节预算限制；不查询没有发送方的
旧地形可靠队列。地形恢复通过应用层缺片请求完成，不依赖可靠整区块通道。
`EntityInterestTracker` 分开保存生物、拾取物、投射物、移动方块、方块实体和库存兴趣组，
避免不同类型的相同数值ID相互干扰。状态按连接对象隔离，断线清理不会延续到新连接。
断线连接的实体兴趣清理由统一兴趣子系统每轮执行，各复制子系统不再重复维护连接清理。

实体进入需发送完整状态；离开和真实销毁是不同事件。常规状态快照缺少某个ID
不代表该对象已删除。局部状态不能依赖全局Bootstrap全集代替进入基线。

骑乘事件发送前为每个既有观察者补齐尚未观察的骑乘依赖组成员；创建基线与骑乘事件
共用有序 Bulk 通道，避免新坐骑尚未创建时事件被忽略。已有实体不重复创建。
骑乘者及坐骑所处地形未达到身体可模拟状态时，身体移动暂停，距离脱离计时也暂停并清零；
恢复地形后继续原距离/时间判据。死亡导致的下马不依赖这一地形前提。

睡眠导致的世界时间加速只由单机或服务端根据完整玩家集合决定。客户端的实体集合
受 AOI 裁剪，不能据此判断所有玩家是否睡眠；客户端保持正常步进并接受服务端世界时间。

玩家运动使用10Hz完整状态快照，而非只发送变化字段：每次包含当前位置、旋转、速度、
视角及适用的骑乘/梯子/潜行状态。静止状态也能在一次丢包后的后续快照中恢复，
不依赖下一次移动触发补发。待发同玩家、同受众快照直接替换为最新状态，不合并旧字段；
快照的骑乘标志必须与接收端当前父身体关系一致；事件和运动跨通道到达时不把坐骑坐标
回落为玩家坐标，也不把上马前的玩家坐标套给坐骑，等待后续匹配的完整快照恢复。
未设置的梯子等可选状态不会被旧快照重新带回。相比增量包，静止时载荷增加，
但服务端仍只向兴趣观察者发送，不为此恢复全局广播。

生物身体使用完整状态快照，经 `StateStream` 发送，客户端按实体比较 `StateTick`。
按连接载荷上限再次拆包时，所有分片必须保留原轮次；序号丢失会使接收端将新位置当旧状态拒绝。
拆包按实际编码后的载荷大小计算，不能仅凭生物数量假定适合直连或中继路径。

拾取物恢复创建基线会纠正已有对象的位置、数量、值、速度和粘附状态，不重放拾取声。
拾取物批量创建只来自当前连接的兴趣进入集合；定向恢复请求也重新校验位置相关性，
不存在读取整个世界拾取物集合的独立全集同步协议分支。
拾取物位置按最多24项的小包发送到StateStream，兄弟小包不由Sequenced互相淘汰；
客户端只平滑跟随权威位置，不重复执行碰撞、脱离方块和拾取飞行模拟，避免旧地形与快照互相拉扯。
接收端按对象比较StateTick，忽略重复或旧轮次，创建/恢复基线同时建立该对象的轮次下限。
在线玩家概要覆盖所有已生成的在线玩家，不受实体AOI限制，供玩家列表计算远处玩家距离和方向。
概要仍为完整列表原子替换，使用可分片的可靠有序Bulk传输，待发列表合并为最新值；
它不是实体移动快照，丢包时可能等待重传，不能拆成会互相覆盖的独立玩家列表。
移动方块创建基线只恢复对象，不播放活塞声；实际伸缩通过独立的 `PistonSound` 瞬时效果投递。
基线及磁盘保存保留运动原始起点和当前速度，重入不把当前位置重新当作平滑加速起点。
实体着火基线直接恢复剩余燃烧时长，不经过权威点火入口；客户端加载不会因权限隔离丢失状态，服务端加载也不重复发送点火事件。
音效等一次性表现使用 Effect 通道，创建、删除与停止仍走可靠生命周期通道。
投射物音效范围根据未缩放的听觉阈值计算，不读取服务端本地音量偏好；接收端继续负责衰减和静音。

方块实体（箱子、熔炉等）按区块观察者建立独立进入/离场生命周期，不再全局广播创建或删除。
初始快照按其坐标过滤；进入基线先于库存增量使用同一有序 Bulk 通道发送。
熔炉进度及停止燃烧的最终状态也使用该通道，避免状态先于实体基线到达而被忽略。
完整熔炉基线包含剩余燃烧时间、热量和熔炼进度；实体离场后重入不依赖下一次增量才能恢复进度。
容器打开响应也使用 Bulk；通过空间授权但尚未观察该方块实体时，先补发完整实体基线，
再返回库存 ID 打开响应，避免跨通道抢先到达导致点击无响应。
非空间、非身体实体仍按其全局业务语义复制。

家具设计是世界级 ID 引用，不随观察者离开区块而删除。设计回收同时考虑地形、
现存物品与离线玩家序列化库存；玩家恢复期间，在库存实体实际加入世界前仍保留离线引用。
在线库存实体已存在后忽略同一玩家的旧离线快照，避免旧库存永久阻止未使用设计回收。

库存的状态观察与操作权限分开：方块容器只向已建立方块实体基线的观察者复制，身体库存按实体观察者及本人连接复制。
玩家库存操作只允许所属连接；方块容器请求使用统一兴趣中心检查空间访问资格。
这里的空间访问资格是兴趣距离，并非玩家到容器的近距离交互限制；不能据此宣称已防止远距离操作。
统一兴趣子系统保留原始相机请求，并周期按最新权威玩家位置重新审批，更新地形生成与分发中心。
位置状态和视野请求跨通道到达时，首次裁剪的中心不会永久滞留；断线同时清除请求意图。
观察到状态并不等于获得修改权限。领地设置请求另外核对发送者 GUID 与领地主人身份，
其协议仅包含实际可变的挖掘、放置、好友及可见性标志，不传固定的方块行为开关。

区块附属状态离场时发送 `ChunkStateResetPackage` 清理客户端缓存；
进入时也先发送清理包，随后发送该区块的告示牌、
可编辑方块和火焰基线。清除与基线使用有序Bulk通道；世界级物品定义和家具设计ID
不属于区块清除范围。

## 发送诊断

电路同步保留20Hz权威时间步，使用连接级完整基线、变化电压及移除坐标。
可见电压仍由统一区块观察者筛选；没有变化时仅发送时间步和空集合。
客户端先重建权威缓存，为待应用时间步创建独立完整状态，再按原电路步推进纠正。
在对应时间步恢复已存在的持久状态元件，并将输出变化的邻居安排到下一步；
随机发生器、锁存器和计数器在客户端使用权威持久值，不独立推进随机或锁存状态。
离场移除和重新进入的值变化由同一连接缓存比较产生，重连建立新基线。
该线格式没有旧协议兼容分支。跨区块电路在加载就绪后完成无损及弱网断网返回的收敛验证，
这不代表冷加载瞬时完成，也不代表所有电路逻辑已经穷举测试。

启用HTTP命令服务并鉴权后，可使用 `game:diagnostics/network/get`：

```json
{"identity":"game:diagnostics/network/get","arguments":{}}
```

返回累计统计及瞬时队列状态：

- `Interest`：当前世界服务端周期性兴趣协调更新的次数、累计/最大耗时及当前线程分配字节。包含该更新中同步调用的区块进入回调和包构造；不包含其他子系统独立调用空间索引的成本、异步工作、后续编码/发送。没有世界时为null；客户端未执行协调更新，计数为0。耗时是墙钟时间，不是进程CPU；分配不是存活堆大小。随世界子系统创建重新计数。
- `Channels`：每通道发送批次数 `Batches` 和编码后字节数 `EncodedBytes`。
- `Packages`：每包类型、通道的实际收件人投递次数 `Deliveries` 和未压缩载荷字节数 `PayloadBytes`。
- `Fanout`：每包类型、通道已完成逻辑消息的数量、不同收件人投递数及平均/最大扇出。消息在出队后建立身份，合并前被替换的快照不单独计数；零收件人消息参与平均值分母。拆片与延期副本共享身份，同一连接只计一次，不同连接即使数值ID相同也分别计数。延期被替换或停止时取消仍保留此前已发送的收件人；尚未完成的消息暂不进入累计值。连接上的直接发送计为单收件人，未连接UDP和发现广播不计入。这里的投递指交给传输库，不代表客户端已确认接收。
- `Routing`：逐连接逐通道筛选的候选检查数、选中包数、累计和最大单轮毫秒数；包括通道与受众资格筛选，不包括兴趣集合构建、序列化、压缩或发送。
- `Encoding`：此NetNode的成功批次编码尝试数、包数、原始和编码字节，及写包序列化/帧编码累计毫秒数。包含尺寸探测、拆包和重试造成的重复编码，不表示实际投递量；帧编码包括压缩策略选择与封装，不是纯压缩耗时。独立宿主上的服务器发现广播不属于 NetNode 实例，未计入；地形预压缩缓存构建也不在此计时范围。
- `PendingPackages`：采样时尚未出队的逻辑包数量，包括拥塞延后重试，不等于传输层数据报数。
- `ReliableQueues`：采样时各连接尚未收到传输确认的可靠载荷字节数（`PendingBytes`），由 Engine 统计；这是瞬时值，需要定期采样才能发现峰值或持续积压。

同一个包发给多个客户端会分别计数。载荷字节与压缩后的批次字节不可直接相加，
也不能把批次数当成包数。统计不包含UDP/IP或传输库开销及重传，因此不是网卡流量。
比较带宽应取同一受控场景和时间窗口的前后差值，并记录玩家数量、位置、视距和事件。
空世界累计值或单包合成测量不能证明整服收益。

Engine 传输宿主为中继信封统一预留 46 字节，因此初始安全 MTU 的应用载荷预算为 461 字节。区块分片固定使用 400 字节载荷，连同元数据和帧头适配该预算；直连也使用这项保守预算，避免连接路径影响区块重组格式。


逻辑连接目标由 Engine 定义：`AddressNetworkTarget` 保存 DNS 名称或 IP 和端口；
`InvitationCodeNetworkTarget` 保存控制地址、六位码和中继策略；`InvitationSessionNetworkTarget`
保存控制地址、不透明会话 ID 和策略。`NetworkHost.PrepareConnectionAsync` 使用调用方提供的 HTTP 客户端，
自动读取信标 UDP 配置并准备同 socket 路径；邀请准备结果保留会话目标，不携带可序列化的票据或参与凭据。
邀请控制通道仅允许 HTTPS，loopback 实验可使用 HTTP。此 API 不负责游戏模组准备或 session 持久化。
信令 HTTP 失败统一返回 `RendezvousException`，保留操作路径、`Kind` 分类、服务端错误码及 HTTP 状态。
`NetworkHost.Resources` 提供连接、待握手、信令请求、候选、注册、邀请、中继准备、路径及通知的近似实时计数，
供实验检查资源收敛；不是跨线程原子快照。宿主停止后这些计数归零，完成所有等待中的传输操作。
游戏加入界面按分类显示本地化提示，诊断日志保留错误码；调用方主动取消保留 `OperationCanceledException`，
不转换为网络故障。联机码或会话不存在、会话满员、容量限制、授权失败及中继不可用可以分别处理。


房主邀请入口是监听宿主上的可选注册。开服使用世界 `P2P` 配置，默认关闭且地址为空。
世界选择实例已安装服务时复制地址和名称，不保存安装记录引用；开启时由现有宿主异步注册并提交房间资料。
信标失败只记录并暴露 `InvitationError`，普通直连/LAN 继续运行。
邀请注册失效时异步撤销旧注册，并按 4、8、16、30 秒的上限退避重新申请；信令恢复后获取新码。
恢复过程中保留普通监听和已建立玩家路径，不重建传输 Host。关闭服务器会取消注册与重试。
Headless 注册成功输出六位码；只读网络诊断的 `Invitation` 返回注册中状态、有效码和错误消息。
`InvitationRelayPolicy` 默认为 Allowed，供邀请加入路径策略使用。信标 URI 的公网控制通道须使用 HTTPS。


GUI 推荐从信令服务器分类的房间列表连接；“联机码”保留为次要操作。联机页固定提供连接、添加、收藏、刷新、联机码和删除：局域网与外部源禁用添加、删除，信令分类另禁用收藏；选中和加载状态继续约束操作。切换分类不重建操作列表。信令服务在内容页面安装和管理。
设置的“诊断与兼容”页面通过点击轮换选择实例级的中继策略，统一应用于房间列表及联机码加入，默认允许；它与世界房主开服配置分别管理，不预设公共信标地址。“恢复兼容设置”同时将中继策略恢复为允许。
房主在游戏菜单的更多操作中查看邀请状态，状态持续刷新，显示该次注册对应的信标地址并允许复制有效码。
联机客户端在游戏菜单的统计信息中查看连接方式：直连、P2P 直连或中继；单机和房主不显示这条客户端信息。
邀请不加入本地收藏或最近服务器标签，正式连接仍验证游戏协议、模组和玩家身份。
连接关闭时显示本地化原因与“确定”按钮，返回服务器列表；邀请用户可再次输入联机码，重新获取路径和服务器信息。
Android 后台可能受到系统网络限制，不保证后台保活或无缝恢复。传输连接关闭后，游戏停止向该连接发送数据，
并在前台处理断线事件，不能继续使用旧连接或因发送到已关闭连接而崩溃。
连接预检与服务器模组核对共用可取消等待对话框；取消按钮或 Esc 会中止请求及下载，
释放尚未转交的连接准备资源后回到列表，不再进入世界或确认重启。


游戏 `ServerConnectionPreparation` 在模组准备等待期间每 20 秒续约路径；消费或关闭时先停止维护。
续约失败不会把旧预检结果当作仍有可用路径，转交前会报告错误。正式连接之后，准备注册被释放，
连接的交通保活和中继数据生命周期由 transport 独立维护。准备对象的并发关闭共享完成状态，
等待同一次资源释放，不会提前报告关闭完成。
取消未消费的中继准备、连接断开或关闭 Host 时，通过当前路由密钥认证的 `relay-close` 控制报文通知中继；
重复通知不会影响其他路由。中继结束转发并释放 socket，端口池清理后可重新分配该端口和新的路由密钥。
通知丢失时保留一分钟空闲回收作为边界。关闭邀请不撤销已建立中继路由，其存活由认证流量维护。
新的中继端点若仍被活跃连接、连接申请或握手占用，房主不确认该分配，每秒重试等待释放，
不更换已有路径或使整个邀请失效。中继准备探测预算为十二秒，仍受整体十五秒准备期限约束。
连接记录各自路由 ID，迟到的断开事件只能释放其原路由，不能按复用端口删除新路由。

信令服务 HTTP 按来源 IP 限流，`Rendezvous:HttpRequestsPerMinute` 默认 600；部署时按同时准备的
参与者数量配置该预算，同一 NAT 下的玩家共享来源 IP。房间目录与邀请控制请求分别计数，浏览不会耗尽续期额度。它与 UDP 注册限流和中继端口池容量分别管理。

### 信令房间目录与加入

联机页面的信令服务器分类从当前实例已安装且启用的服务读取公开房间。第二个筛选按钮先提供“全部”，汇总所有启用服务的房间，再列出各个服务供单独筛选；房间行标明来源。个别服务访问失败不丢弃其他服务的结果。目录浏览只发送HTTP读取，不创建参与者或申请中继；点击房间后使用其联机码及当前服务地址进入已有连接准备流程。手工联机码为独立的底层入口：直接填写信令URL、六位码及本次中继策略，不要求预先安装服务，不更改全局策略或安装列表；提交后使用相同准备路径。房间不收藏、不写最近记录或本地服务器目录。中继策略是加入方的实例偏好，独立于世界P2P设置；列表展示的可用方式不保证实际穿透成功。
